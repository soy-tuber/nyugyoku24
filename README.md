# nyugyoku24 — 入玉宣言法24点法の終盤特化エンジンと実証データ

将棋の**入玉宣言法（24点法）**を目的関数に持つ相入玉終盤エンジンと、
floodgate 公開棋譜 186万局から得た実証データ。

現代の将棋AIは27点法を前提に作られている一方、プロ公式棋戦は2013年10月以降
**24点法**を採用している。このリポジトリは、その差が実戦でどう現れるかを測り、
24点法の目的関数を持つエンジンを実装したものである。

📄 **[解説（簡易論文）](https://soy-tuber.github.io/nyugyoku24/)**

## 主要な結果

### 1. 24点法の勝ちは、定義上「駒を取るゲーム」である

各陣営の駒の総点は **27点**（飛角10 + 歩9 + 金銀桂香8）。宣言点数はその部分集合なので、
**自分の駒だけをかき集めても上限は27点**にしかならない。

| 目標 | 必要な駒取り |
|---|---|
| 無勝負（24点） | **不要**。自分の27点のうち24点を持駒か敵陣に置けばよい |
| 勝ち（31点） | **相手から最低4点を奪わねばならない** |

27点法が後手有利なのも同じ理屈である。先手28点は最低1点の駒取りを要するが、
後手27点は駒取りゼロで到達できる。

### 2. 2つの宣言条件は難易度が正反対

| 条件 | 満たす局面 | 達成手段 | 難易度 |
|---|---:|---|---|
| 敵陣三段目以内に10枚 | 8.9% | **打ち込み**（点数不変のまま1枚進む） | 易しい |
| 31点 | 13.8% | **駒取りのみ** | 難しい |

持ち駒は点数に計上されるが10枚条件には計上されない。したがって
**持ち駒を敵陣に打つと、点数を1点も失わずに10枚条件が1枚進む**。
本エンジンはこれを利用して、実戦のエンジンが中央値6枚で止まった局面から
20手で敵陣4枚→13枚に到達する。

10枚条件が満たされていないのは難しいからではなく、既存エンジンが目指していないためである。

### 3. 漏斗

打ち切り引き分けとなった相入玉局 12,670サンプル（先後別）:

| 段階 | 割合 | 通過率 |
|---|---:|---:|
| 所有31点以上（勝ちの必要条件） | 32.8% | — |
| かつ宣言点数31点以上（変換済み） | 13.8% | 42.0% |
| かつ敵陣内10枚（宣言勝ち） | **2.8%** | 20.6% |

所有31点ある側の58%が「勝てる材料を持ちながら変換できず」に終わっている。
取り残し（敵陣外で死んでいる自駒）の中央値は7点。

### 4. floodgate は2024年に Max_Moves を 256→512 に変更していた

これにより相入玉局の宣言到達率が **19.4% → 41.4%** に跳ね上がる（強豪限定）。
2024年を挟いだ年次比較はすべて無効になる。
「エンジンは入玉がヘタ」に見えていたものの相当部分は、能力ではなく手数上限の産物だった。

## 中身

```
engine/       相入玉エンジン一式
  engine_decl24.py   入玉宣言法24点法。宣言判定はここ
  engine_unified.py  「取られない・取りまくる・勝ちが見えたら勝ちに動く」統合版
  engine_learn.py    重みを外から与える版 (自動調整の対象)
  features.py        特徴量の抽出
  roles.py           攻撃側/防御側の役割固定と攻防入れ替え判定
  tune_spsa.py       SPSA による重みの自動調整
  engine24.py        持将棋 (合意) 用。数え方が違う別ルール
tools/        データセット構築と解析
  make_conformance.py        適合性テスト集合の生成 (合成。宣言すれば負ける陰性側)
  fetch_conformance_real.py  同 (実戦由来の陽性側。HuggingFace から層化サンプリング)
  probe_dlshogi_nyugyoku.py  dlshogi の入玉用入力特徴の実測
positions/    floodgate から抽出した相入玉局面 (ベンチマーク用)
tests/        入玉宣言法の規則テストと、24点法の適合性テスト
weights/      調整済みの重み
docs/         解説 (GitHub Pages)
```

## 動かす

```bash
pip install cshogi
python tests/test_rules.py          # 規則テスト
python engine/test_decl24.py        # 自己対局
python engine/tune_spsa.py 150 40 2 100   # 重みの自動調整
```

`positions/` に floodgate から抽出した相入玉局面が入っているので、
棋譜アーカイブ（2.7GB）が無くてもベンチマークは再現できる。
棋譜そのものから作り直す場合は `tools/build_nyugyoku_dataset.py` を使う。

## 未検証事項（正直な注意書き）

- **外部エンジンと1局も対戦していない。** 重み調整の「ホールドアウト77.8%」は
  「自分の初期値より強い」という意味しかなく、絶対強度はまったく不明である
- **USI未実装。** GUIにも対局場にも接続できない
- **相入玉限定。** 序盤・中盤・詰みは扱えない
- **Python で約23k nps、depth 2〜3。** 実用的な棋力には遠い
- 打ち切り局の再採点は「その時点で裁定したら」という反実仮想である

現状は「目的関数の実証と測定器」であって、対局用のエンジンではない。
